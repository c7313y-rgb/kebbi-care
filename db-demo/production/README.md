# Kebbi Care 4.0 共有DB版

GitHub公開版の本番設置用ソースです。個人マスタ、管理キー、実際のケア記録は含めません。

## 本番の保存先とアクセス

- 所有者：generousadmin@gmail.com。
- 画面：Google Apps ScriptのWebアプリ。PC・Mac・スマートフォン・タブレットのブラウザでURLを開き、共通の管理キーでログイン。
- DB：所有者の非公開Googleスプレッドシート。GitHubにはデータを保存しない。
- 原本：Google Driveの「Kebbi Care 共有データ / CSV原本」。
- バックアップ：同フォルダ内の「自動バックアップ」。更新前と毎日、復元用JSONを作成。期限による自動削除なし。
- バックアップには画面の状態と各DB表を含む。DB削除等からの完全復旧では、管理者・開発者がJSON内のtablesを新しいDBへ復元する。画面のJSON復元は、既存記録を保持して未登録の記録・再生履歴を追加する方式。

## 初回設置

1. generousadmin@gmail.com で https://script.google.com/ にログインし、新しいプロジェクトを作成。
2. スクリプトを5つ用意：Code、MailImport、CareCore、CareServer、DriveImport。対応する `.gs` の内容を貼り付ける。
3. HTMLを2つ用意：Index、Advanced。対応する `.html` を貼り付ける。
4. プロジェクト設定でマニフェストを表示し、appsscript.jsonを置換。Gmail API v1がサービスに表示されることを確認。
5. CareServer.gs を開き、関数 `initialSetup` を実行し、Googleの権限を許可。実行ログの管理キー・閲覧キーを保管。（末尾が `_` の関数はエディタの関数一覧に表示されないため、`setupMailImport_` と `setupCareStorage_` をまとめて呼ぶ入口として追加。完了後の再実行は何も変更しない。）
6. 同じ実行で、保存フォルダと毎日2時台（日本時間）のバックアップが作成される。
7. ウェブアプリとして新しいデプロイ。実行ユーザーは自分、アクセスは全員。アクセスキーによる認証はアプリ側で実施。
8. 発行された `/exec` URLを開き、管理キーでログイン。「設定・データ保存」からマスタXLSXを取り込む。
9. 「データ取込 → Google Driveから取り込む」で、後から対象フォルダURLを登録できる。任意で5分ごとの自動取込とログイン時確認を有効にする。
10. 設定内の「従来の連携・管理設定」から、Kebbi端末とGmail送信元を設定。従来APIとメール取込も同じDBを使用。

## 既存環境の更新

DB_IDを保持したまま8ファイルを更新し、setupCareStorage_を実行する。必要な追加表は自動作成。デプロイのバージョンを更新する。既存の管理キー・端末トークンは維持。
新規DBの7項目は「食事量・排尿・排便・体調変化・不穏行動・睡眠状況・服薬状況」。古いDBの項目ラベルを勝手に読み替えない。対応できない旧項目は保持し、新しい8区分の統計へは混ぜない。

## CSV取込

- 手動アップロード、Drive直接取込、Gmail添付は同じ照合規則を使用。
- 利用者ID・職員ID・施設をマスタと照合。氏名からIDを推測しない。
- 日時、本文、要約、8区分、複数の受取履歴、健康チェック設問・回答・スコアを保持。
- 1ファイル5MB・10,000行、1回20ファイルまで。Google Sheetsの1セルの制約に合わせ、1件の記録は45,000文字以内。
- 記録ID・施設・利用者・種別で同一記録を判定。内容が異なる既存の原文等を自動上書きしない。空欄項目・再生履歴の追加は可能。
- Driveは登録フォルダ直下のCSVを対象。自動実行は1回10ファイルまで、続きは次回。失敗したファイルも後続の巡回で再確認。
- 受取職員と受取日時が揃った履歴だけを「受取あり」として集計。
- CSVに無い原文・要約等をAIで補完しない。元のCSVとバックアップを保持。
- JSONバックアップが作れない場合は、共有記録へのCSV反映を停止。

## 提供画像と操作ガイド

Index.htmlに提供画像・8場面の操作ガイド・Kebbi再現音声を内包しています。音声ファイルは提供音声を参照してMac内で生成済みです。外部音声APIや契約は不要です。生成モデルは配信アプリに含めません。PC・タブレット・スマートフォンで同じ音声を再生します。設置するファイル数やGoogleの設置手順は従来と同じです。

ダッシュボードの管理統計は、初回受取までの中央値・健康チェック実施記録率・未受取経過日数です。日時未記録のデータは時間統計から除外します。


## Mac以外の音声再生

案内は共通のMP3をブラウザで再生します。Windows（Edge/Chrome）、iPhone/iPad（Safari）、Android（Chrome）、Mac（Safari/Chrome）を対象にしています。音声生成モデルやMac専用ソフトを利用端末へインストールする必要はありません。音声はKebbiだけです。

「操作ガイド → 案内を再生」をクリックまたはタップします。1つの再生要素を使い続け、自動再生が制限されたときは自動案内を解除して、再生ボタンから再開できるようにしています。タブを離れる・画面を閉じる操作で音声を停止します。

127.0.0.1は、このMac上で画面を確認する一時URLです。ほかの端末では、Googleに設置した本番の /exec URL を使用します。音声形式にMac限定の制約があるという意味ではありません。実機での受入確認は本番設置後に行います。

設計資料: [WebKitの再生方針](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)、[Chromiumの自動再生方針](https://www.chromium.org/audio-video/autoplay/)。


## 2026-11-12 更新（CSV取込の検査と修正）

本番で反映するには、Apps Script の CareCore.gs・CareServer.gs・Index.html をこのフォルダの内容に差し替え、新しいバージョンとして再デプロイしてください。DB（スプレッドシート）の変更は不要です。

- Kebbi DBの「記録CSV」「再生履歴CSV」をそのまま取り込めるように修正（「記録した職員」列、played_at と received_at の併記、状態＝確定／途中保存）。
- 記録IDのない行を、施設・種別・利用者・職員・日時・本文で同一判定。後から再生履歴の列が増えたCSVを取り込んでも二重登録しない。更新前に取り込んだID無しの記録にも対応。
- DBの記録ID（csv-…）で出力されたCSVを取り込んでも、元の記録に統合。
- 項目行形式で同じ項目が複数行ある場合は、エラーにせず1件の記録へ追記。
- 8区分の表記ゆれ（食事摂取量、体調、睡眠状態、内服、その他、「6.睡眠状況」など）に対応。「排泄」は排尿・排便を判別できないため、取り込まずに修正を求める。
- 表計算ソフトで保存したCSV（末尾の空列、行末の空欄省略、タブ区切り、「2026年11月12日 13時5分」、全角の数字・ID、IDの大文字小文字）に対応。
- ダッシュボードに「8区分ごとの記録件数」を追加。記録検索の対象に確定本文・利用者ID・8区分の内容を追加。
- 再生履歴だけのCSVを再取込した場合も「登録済み」に数える。取込時のシート読込回数を削減。
