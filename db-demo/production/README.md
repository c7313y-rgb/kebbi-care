# ジェネラス用 Gmail連携版の設置

このフォルダは Google Apps Script に設置する本番用ソースです。公開デモのブラウザ保存領域とは独立しています。受信箱は generousadmin@gmail.com、CSV送信元は管理画面で後から登録します。

## 初回だけ行う作業

1. generousadmin@gmail.com で Google にログインし、https://script.google.com/home/start から新しいプロジェクトを作成。
2. `Code.gs` を本フォルダの同名ファイルの内容で置換。スクリプト `MailImport`、HTML `Index` を追加し、対応する内容を貼付け。
3. プロジェクトの設定で「appsscript.json マニフェスト ファイルをエディタで表示する」をオン。本フォルダの `appsscript.json` を貼付けて保存。
4. エディタのサービスに Gmail API v1 があることを確認。なければ「サービス +」から Gmail API を追加。標準の Google Cloud プロジェクトを別途使う場合は、そのプロジェクトでも Gmail API を有効化。
5. 関数 `setupMailImport_` を選び「実行」。所有者が Google の許可画面で Gmail の読み取り、スプレッドシート、Drive、トリガーの権限を許可。
6. 実行ログの管理キーを会社の安全な保管場所に控える。キーを GitHub、マニュアル、チャットに掲載しない。
7. 「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザーは「自分」。アクセスは初期運用では「自分のみ」。`/exec` URLをコピー。
8. 公開入口ページにURLを登録し、本番管理画面へ進む。発行した管理キーでログイン。
9. 「マスタ」からジェネラスのマスタ登録XLSXを読み込み、利用者ID・職員ID・入力権限を確認。
10. 「メール取込」でCSV送信元、施設、取込開始日、文字コードを保存。「今すぐ取り込む」でテストし、「5分ごとの取込を開始」。

## 設定と動作

- 保存先DBは同アカウントの非公開Googleスプレッドシート。`DB_ID` に記録される。共有設定を全員公開にしない。
- Gmail APIは読み取り専用。メールの送信・削除・既読変更は行わない。
- 定期取込は作成したアカウントで約5分ごと。起動時取込は管理者ログインが成功した際に1回。閲覧キーでは動かない。
- 同時実行をロックし、添付単位と記録単位で重複を除外。既存記録の内容変更は自動上書きせず要確認にする。
- 添付1MB、1ファイル500行、1回20メールまで。続きは次回実行。過去のメールは開始日以降だけが対象。
- CSVは全行を検証した後に保存。形式・IDエラーが1件でもあればそのファイルを取り込まない。他のファイルは処理する。
- Googleの障害等で保存中に中断した場合は一部の書込みが残ることがある。同じファイルを再試行し、IDと内容の一致を確認して残りを登録する。
- 自動取込は常に途中保存（確定待ち）。CSV内の「確定」をそのまま承認として扱わない。
- 登録先は記録のみ。利用者・職員マスタや再生履歴のCSVをメールで更新する機能は含まない。
- メール原本はGmailに残す。健康チェックのスコアや旧CSVの受取日時など、管理画面の保存項目にない補助列はメール原本で確認する。過去の受取を再生完了として登録しない。

## 対応CSV

Kebbi既存ひな形の「申し送り」「健康チェック」「看護師申し送り」、および本管理画面の記録CSV出力と英字列CSVに対応。申し送りは同じID・利用者の項目行をまとめ、健康チェックは同じ実施ID・利用者の設問行をまとめる。

英字列：`record_id,type,resident_id,staff_id,recorded_at,source_text,ai_summary,confirmed_text,item_1,...,item_7,item_none`。`recorded_at` と `staff_id` は必要。申し送り・健康チェックは `resident_id` も必要。本文のいずれかが必要。`type` 省略時は handover。`record_id` 省略時は内容から安定したIDを生成。同じ内容は同じ記録として扱うため、独立した記録には一意のIDを付ける。

文字コードはUTF-8（BOM可）またはShift_JIS。CSVの列名が違う場合は「開発者向け 列名の対応」にJSONを設定。例：`{"staff_id":"担当者コード","recorded_at":"記録時刻"}`。名前からIDへの推測は行わない。

## 更新方法

4ファイルを差し替え、`setupMailImport_`を再実行。DB_IDが同じなら既存データを保持し、必要な表だけ追加する。デプロイを管理から新しいバージョンに更新。コード編集だけでは既存 `/exec` に反映されない。

## 検証の範囲

添付取得・形式検証・保存・再試行・重複排除・画面操作を模擬環境でテスト。実アカウントのOAuth許可と実メール受信テストは設置者が行う。GitHub公開のみではGmail接続は有効にならない。
